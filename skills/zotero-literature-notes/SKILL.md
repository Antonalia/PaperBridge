# Zotero → Obsidian 文献笔记

## 目标与适用范围

完成一条有来源、可追溯的链路：**Zotero 原文 → 原生 PDF 标注 → Bridge 导入 Obsidian → 在同一笔记展开详细解读**。默认使用中文解释，保留英文术语、数学公式和可核验的数值；遵循用户指定的语言与范围。

用户只要求检索或解释、没有要求标注/保存时，不触发外部写入。用户明确要求上述完整流程，或在“文献笔记”任务中明确要求先标注再导入时，该授权覆盖相应标注和导入；先生成具体 plan 并审阅预览，再执行，不因工具写有“after authorization”而重复索取已经获得的许可。授权不扩展到修改插件设置、删除已有标注、移动无关笔记或发送消息。

## 1. 确认论文并获取原文

1. 调用 `zotero_status`，确认 Bridge 在线及 `write_enabled`；保持 Zotero 打开。
2. 用户给定题名/关键词时使用 `zotero_search`；明确指向当前选中条目时使用 `zotero_selected_items`。仅使用工具实际返回的 item/attachment ID。
3. 核对完整标题、作者、年份、arXiv/DOI 和版本。同名论文要区分；如果本库匹配唯一且符合上下文，可以直接继续。确有多个不能辨别的候选时，再请求必要澄清。
4. 分批调用 `zotero_read_pdf` 阅读正文和附录；页码是从 1 开始的物理 PDF 页，每次最多 20 页。覆盖方法、实验表、消融和重要附录，不以摘要或二手介绍代替全文。
5. 需要精确选段时使用 `zotero_find_pdf_text`。只使用当次工具返回的 locator；扫描 PDF 缺乏文本时，明确 OCR 限制，不能编造定位。
6. 相关文献默认限于主论文正文、相关工作、参考文献或实验中实际引用/讨论的工作；先核对原文中的出处，再决定是否需要展开。用户在历史对话提过、库中有笔记或主题相近，都不是自动加入对比的依据。只有用户在当前任务明确要求额外对比/拓展时，才加入原文外工作，并区分其与作者的讨论。对主论文及每篇拟引用的相关论文，先用 `zotero_search` 检索本库，核对准确题名与版本；短词可能匹配作者并产生分页，优先完整题名或辨识度高的词组，必要时翻页，不能把截断结果当作未收录。库中有 PDF 时优先读取本地原文，再判断继承、差异与实验证据；引用跳转按下方“来源引用优先 Zotero”执行。库中未收录或需核实最新版本、仓库更新时查原论文/作者材料，联网核实不意味着把已收录论文的正文引用改成网页。控制范围，不将单篇精读冒充系统综述。

## 2. 检查已有标注；缺失时先创建

调用 `zotero_list_annotations`。没有标注时，**先创建有意义的原生标注，再准备 Obsidian 导入**；“没有可导入的标注”不是跳过 Bridge 手写导出的理由。

有标注时复用已有内容，不无条件重做。按用户范围补充遗漏，避免相同位置、相同含义的重复标注。

选段应覆盖论文的证据骨架，数量按论文复杂度决定：研究问题与核心结论、模型总览、关键机制、训练/推理差异、主结果、关键消融、测量条件与限制。不要整页泛黄或把全文当作标注。

- 文字使用 `zotero_prepare_annotations`。`locator_ids` 只来自已读原文；同一条标注只组合同页连续定位段。
- **按完整句子选段，禁止按固定行数截取**：`read_pdf` 的 passage 通常是一行，不等于一句或一个语义段。先确定原文中的完整句子，再用 `zotero_find_pdf_text` 得到该句的精确 locator；同页多句需完整覆盖至最后一句句号。首行不能从上一句中间起，末行不能吞入下一句的开头。只在用户明确要求短语/公式/片段时选择相应边界。
- 匹配时使用 PDF 实际提取文本，包括行尾断词、数学字符和空白；不得把自行去连字符或翻译后的文本当定位依据。双栏 PDF 的提取顺序可能交错，不能用 passage 数组相邻直接证明同一段连续。检索无命中时回查原文与页面，而不是退回整行计数。
- 高亮文本保持原文；中文总结、术语解释和数值含义写入 `comment`，不要用译文替换来源文字。
- 重点用 `emphasis: important`；不指定颜色，除非用户明确要求，以便沿用插件颜色设置。
- 图/表先调用 `zotero_render_pdf_page` 并实际查看返回图像，再用返回的 `render_id` 与真实渲染像素矩形调用 `zotero_prepare_image_annotation`。图使用 `region_kind: figure`，表用 `table`；不得猜坐标或照抄另一份 PDF 的坐标。
- 图注解释结构中的数据流；表注解释指标、基线、差值与实验口径。标注以原文证据为主，不将阅读推断伪装成作者结论。

审阅 prepare 返回的文本、定位、颜色与图片裁剪预览，确认内容准确并有任务授权后调用 `zotero_apply_annotations({plan_id})`。该操作只添加原生标注，不改变 PDF 内容。记录返回的 annotation ID，并再次检查标注确实存在。

### 文字边界与高亮几何质量

prepare 预览必须与选定的完整原句一致；逐条检查开头、结尾和下一句是否被误选。首次在某 PDF/版式创建文字标注时，先落地一条有任务价值的完整句子，再用 `zotero_list_annotations` 检查实际 `position.rects`；通过后才扩大批量。

多行句子通常需要同一 annotation 内多个矩形，这本身正常；一个句子跨多行不应被误拆成多个独立 annotation。检查两个层次：不同标注是否覆盖同一来源文字，以及同一标注的相邻行矩形是否相交。相邻矩形出现可见重叠/颜色变深时，应报告几何问题并暂停后续文字高亮；数学上下标可能需要更高的框，不能单靠固定高度裁切。

已知本地 Bridge 0.1.10 的 `read_pdf` 使用行 bbox，精确 `find_pdf_text` 使用匹配字符 bbox 的逐行并集。它们可能继承超过行距的字体包围框；完整句子检索能纠正横向句末，但**不保证消除纵向矩形重叠**。发现此问题时不能猜坐标、绕过 locator 或新增相同区域来“修正”。需要支持更合适高亮几何的 Bridge 修复或原生编辑能力。

当前工具的 `apply_annotations` 仅新增，不编辑/删除既有标注。同一 plan 重放的幂等性不等于新 plan 会自动去重。修正旧高亮前，确认有可用的原位编辑/明确替换流程；没有时只准备修正预览，说明未改写，保留已有标注，不直接操作运行中的 Zotero 数据库，也不把注释文字改好冒充高亮已修好。

## 3. 通过 Bridge 导入，遵循真实目录与链接设置

1. 首次确定保存位置时，调用 `zotero_prepare_obsidian_import`，传真实附件 ID 并保留注释，**先不传 `target_note`**。让 Bridge 根据当前插件配置读取 vault、top folder、folder layout、条目所属 collection 的完整父子路径及链接偏好。实际检索结果只有 item/PDF ID 时，不能据此猜分类；读取 prepare 返回的 `collection.collection_id`、`collection.path` 与 `note_path`，必要时读取插件 `obsidian_snapshot` 的 `collections` 和 `settings`。保存位置必须有这次真实工具结果支撑。
2. 当配置为按 Zotero 分类层级（`folder_layout: collections`）时，目录必须是 **仓库 / 配置的顶层目录 / 已确认的完整 Zotero 分类路径 / 文件名.md**。顶层目录与分类路径是相加关系，不是二选一。例如 top folder 为“文献笔记”、分类路径为“具身智能”时应是 `文献笔记/具身智能/论文标题.md`；若分类还含父子层级，则保留全部层级。不能只放顶层、只取叶分类、按论文主题自造分类，或改成库根的同名目录。目录字符的安全化使用 Bridge 已解析的结果，不能把分类名称当任意 shell 路径拼接。配置为平铺时才使用平铺结构，不改插件设置来迁就旧路径。
3. 多 collection 时检查工具返回的真实候选、当前有效选中分类和用户指定分类；能唯一确定就使用相应 `collection_id`，必要时重新 prepare。确实无法选择才请求澄清，不默认取第一个，不静默退回顶层。严格分类模式下无法读取分类、条目未分类或解析失败时，应先报告/解决缺失信息，不把顶层当作已符合分类要求。

只有用户明确指定文件位置、更新真实现有笔记，或需要调整文件名时才传 `target_note`。**改变文件名只允许改变 Bridge 已确认路径的最后一个文件名部分，必须保留顶层目录和完整分类父路径**；再 prepare 核对目录、collection 与 action。用户要求独立重生成，也在这个已确认分类目录内选择新的论文题目文件名，不在顶层直接新建；不复制旧正文、不覆盖旧文件。用户明确要求本次遵循分类层级时，已存在的错误位置不能成为继续写错目录的理由；先安全迁移原笔记、图片相对链接与同步元数据，再以新路径更新。只有用户明确要求例外位置才覆盖配置，报告其与分类默认位置的区别。

4. 若目标笔记已经清理过内部标记，先用本技能 `scripts/note_metadata.py restore --vault <真实仓库> --note <真实笔记绝对路径>` 恢复旁侧元数据中的管理边界，再重新 prepare；不要把缺少标记的干净笔记直接当作未导入而重复追加。恢复会保留管理块之外的用户修改；若原文块被编辑或无法唯一定位，先核对变更，不猜位置、不覆盖。审阅返回的路径、标注、图片与链接预览；在已有导入授权范围内调用 `zotero_apply_obsidian_import({plan_id})`。以成功结果确认写入，不能把 prepare 成功当作已经保存。
5. 若提示 note/settings 已变化，重新准备一次并核对差异，不重放过期计划；反复冲突时保留草稿并报告具体阻碍。无标注错误返回第 2 步处理。
6. 不修改用户的插件配置来迎合预想目录，不以 shell copy 绕开正常导入流程，也不声称直接写文件等于 Bridge 导入成功。

Bridge 默认负责按类型控制标注链接。人工补充标注深链接前，调用 `zotero_get_obsidian_link`，使用 apply/list 返回的 annotation ID 与 `content_kind`。返回 `enabled=false` 或 `url=null` 就省略链接；不要手工构造链接绕开关闭的文字/图/表链接偏好。

### 来源引用优先 Zotero

正文与参考表遵循同一规则：**引用的论文已在 Zotero 中，就直接链接 Zotero；未收录的论文才使用原论文网页。** 原文入口、相关工作、公式、图表、附录和实验数值都适用。不要因为联网查过资料就把库内论文的引用指向 arXiv/DOI 网页，也不要在同一个引用后重复附上网页替代入口。保留 arXiv/DOI 标识作为论文身份文字即可；用户明确需要网页、另一个未入库版本、作者项目或代码资源时，才按该用途提供网页链接。

- 一般论文引用使用 `zotero_search` 实际返回的 `zotero_uri`，直接选中对应条目。库内有条目但没有 PDF 时，也使用条目链接，不默默回退网页。
- 引用特定公式、图表、段落或数值时，优先打开实际已读的 PDF 对应页。当前 Bridge 返回个人库 `u-XXXXXXXX` 附件 ID；核实它是该版本的 PDF 后，仅去掉 `u-` 前缀取得附件 key，使用 `zotero://open-pdf/library/items/<附件key>?page=<物理页码>`。必须使用 PDF 附件 key，不能用父条目 key。页码由 `zotero_read_pdf` 核实，范围为 1 到 `page_count`；印刷页码与物理页码不同时区分，不猜页码、ID 或未支持的群组库地址。工具提供可用的页链接解析器时优先使用解析器。不能确认附件或页码时，保留条目链接及已核实的位置描述，不伪造精确跳转。
- 原文跨多页时链接关键证据所在页，必要时给两个相邻页链接；标签保留图表/公式编号和明确页码。链接贴近它支持的解释，不只放在末尾。例如 `[论文名，附录 Table A2，第 10 页](zotero://open-pdf/library/items/<已核实附件key>?page=10)`；示例占位符不得写入最终笔记。
- 来源/文献引用与 `?annotation=...` 标注链接是不同用途。标注深链接仍调用 `zotero_get_obsidian_link` 并尊重相应显示设置，不通过来源引用伪装标注链接，也不因新增文献引用而重置插件偏好。用户明确关闭所有 Zotero 来源链接时遵循用户要求。
- 未收录文献使用可核验的原论文/作者网页；查询失败或 Bridge 不可用不等于“库中不存在”。不能确认时说明检索限制，不声称已经完成库内核对。同一论文重复引用复用同一经过核实的映射，不在网页与 Zotero 之间随机切换。

## 4. 在导入的同一笔记展开详细解释

导入不是任务终点。读取成功写入的真实笔记，在 **Bridge 生成块之外** 增补人工精读内容，保留原有手写内容、标注标识、资源路径和插件管理区。只更新本技能拥有的展开区，后续重复执行不整篇覆盖、不重复追加。

推荐以明确标记包裹展开区，例如：

```markdown
<!-- literature-notes:expanded:start -->
## 论文详细解读
（经原文核对的人工整理内容）
<!-- literature-notes:expanded:end -->
```

若已有展开区，可更新该区；若用户后来编辑了该区，先读取并保留其实质增补，不盲目替换。没有此区时在管理块外创建。对已有的详细手写笔记，优先复用或整理其内容，避免形成内容相同的两份展开。将原文管理块移动到相应解释段附近时保留其内容和完整边界；人工展开区中嵌入的 Bridge 块也必须保留，不能替换整个展开区时顺带删除。

模型论文精读先读取 [references/model-explanation.md](references/model-explanation.md)，按实际数据流详细讲方法：输入与张量 → 模块内计算 → 输出与更新依赖 → 公式逐项解释 → 教学例子 → 训练和推理。相关原文、图表和引用穿插在解释所需的位置，不仅堆在末尾。用户给出的风格样例应实际读取；无法访问就请求片段，不假装已经读到。

### 标题、发表信息与问题导向开头

Obsidian 顶部的内联标题来自**文件名**，正文 `# 标题` 不会改变它。默认把真实笔记文件名设为论文完整题目，让内联标题承担主标题；Windows 禁用的文件名字符要做最小替换，例如英文冒号 `:` 改为全角 `：`。不把“Skill 独立重生成”等执行标签当成论文标题。独立生成时不覆盖现有同名笔记，有冲突才使用简短可区分的版本后缀，并报告真实路径。

用户启用内联标题（或截图确认顶部已显示文件名）时，正文从发表信息表开始，**不再写重复的一级标题**；若用户明确关闭内联标题，才在正文保留一个论文题目的一级标题。不为解决重复标题而改动全库的显示设置。来源链接中的论文简称可以正常使用。重命名现有笔记时检查同名目标、引用与图片相对路径，保留原有内容并迁移本技能的旁侧同步元数据；不能只改正文 H1 就声称改了 Obsidian 标题。

论文完整题目只作为笔记主标题，不在开头正文或信息表中重复。标题下用简洁表格列出**发表日期**、**期刊/会议**；不再以作者、版本、页数和完整题名拼成身份介绍段。日期与发表载体依据核实过的 Zotero 元数据及对应原文填写；期刊论文用期刊名，会议论文用会议名，预印本明确写预印本平台。只知道预印本日期时标注“预印本发布”，不能冒充正式发表日期；本库与原文未提供期刊/会议时写“未标注（arXiv 预印本）”或“未确认”，不编造刊名或声称尚未发表。来源链接可放在相应表格单元格，库内原文仍链接 Zotero。

表格后的第一段直接讲论文要解决的具体问题：现有方法遇到什么矛盾或不足，为什么值得解决，本篇采取什么核心思路。采用连贯解释，引出后面的模型方法；不重新罗列论文身份或只列模块名称。方法简称可在解释和引用中正常使用，避免重复完整题目。

详细程度随论文与用户要求调整。模型论文至少解释下列要点：

- **开头与研究问题**：题目作主标题，发表信息用简洁表格；正文从研究问题、现有不足、核心思路与对照设定讲起。
- **文献脉络**：以原文实际引用/讨论的直接先行工作为范围，解释继承、差异和可能兼容的结论；库内论文链接 Zotero，未收录才链接原论文网页。
- **结构**：输入输出、张量/时间尺度、编码器、主干、交互、解码器与条件信号；用流程图或已导入原图辅助。
- **机制与公式**：每个展示公式逐一解释全部变量及上下标、索引、常量和运算，说明含义、来源、可核实的形状/范围、归一化与归约轴，以及输出如何接回模型。每个核心机制用具体数字演示输入、中间计算和结果，相邻公式可共用贯穿例子；教学选值和推导明确标注，不冒充论文配置或实测。细则见 `references/model-explanation.md`。
- **实验**：数据、训练资源、评价 protocol、主要结果、有效基线与消融。比较绝对百分点与相对百分比；保留任务平均/类别平均的区别。
- **效率**：硬件、分辨率、采样步数、计时包含/排除项；不直接跨不同条件混算加速比。
- **结论与限制**：分开写作者报告、阅读推断、未证实内容。识别累积消融、重训练对照、单 seed、饱和基准、有限实机/OOD 范围。
- **参考文献与知识连接**：遵循 Zotero 优先路由，页码/图表编号与来源链接就近标注；仅给库中真实存在、与本次解释有关且在原文范围或当前用户明确要求范围内的笔记添加双链；不因历史对话提过就加入。

保留可核验的引用与公式，不大段复制原文。写入前记录已有内容；若 vault 在默认可写范围外，使用必要的文件权限流程完成已获授权的局部编辑，不能顺势修改无关文件。

### 正文不留内部管理标记

完成导入和精读后，执行 `scripts/note_metadata.py clean --vault <真实仓库> --note <真实笔记绝对路径>`。该脚本把 `codex-zotero-*` 和 `literature-notes:expanded:*` 管理注释移入仓库的 `.codex-zotero-sync` 旁侧元数据，保留正文、原文、图片、公式和启用的来源链接。最终笔记不显示这些 HTML 注释、转义后的标记或内部 ID 清单，也不添加执行流水说明。后续同步/修改先恢复边界，结束再清理；元数据与笔记必须一同保留。此默认格式不要求更改 Zotero 原生标注或插件配置。
