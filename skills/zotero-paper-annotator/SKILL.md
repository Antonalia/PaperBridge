# Zotero 论文自动批注

把一篇论文的论证骨架、关键方法、核心公式、实验证据和适用边界转成 Zotero 原生注释及一份可独立阅读的 Markdown 讲解。默认中文解释，保留英文术语和原文符号。按用户指定语言、深度及输出位置调整。

## 连接与范围

- 发现当前可调用的 `zotero_local` 工具，先调用 `zotero_status`，读取实际版本、写入开关、最新 `annotation_rules` 和颜色偏好。PaperBridge 必须运行在已打开的 Zotero 中；工具名可能仍使用旧的 bridge 名称。
- 从 `zotero_search` 或 `zotero_selected_items` 返回的条目与附件 ID 识别目标，核对标题、版本、年份和 PDF。仅用返回的 ID，不从题名猜附件 ID。存在真正无法区分的多个候选时，先继续可独立进行的工作，再向用户澄清。
- 用户请求“自动标注这篇论文”“用这篇论文试跑”等，已经授权为该论文新增相关批注；在自主检查预览后完成写入，不重复索要同一授权。仅请求摘要、预览或 skill 草稿时，不写 Zotero。
- 写入关闭、连接失败或必要能力缺失时，完成能完成的阅读和本地讲解，报告具体阻碍；不修改插件设置、数据库或安装环境来绕过限制。
- Markdown 保存到用户指定目录。没有指定时用本次工作区的交付目录；projectless chat 使用 `outputs/`，中间数据使用 `work/`。不因有 Obsidian 配置就默认导入笔记；用户请求导入时使用 bridge 的 prepare/apply 导入能力并遵守其配置。

## 阅读与选点

1. 用 `zotero_read_pdf` 阅读正文与理解方法所需的附录；每次最多 20 个物理页，页码从 1 开始。并用 `zotero_list_annotations` 读取现有注释，建立重复检查依据。
2. 梳理论文要解决的问题、已有方法缺口、关键贡献、机制、训练或推理过程、主要实验、局限。由这条论证链选择重点，不按固定数量、行数或每页配额标注。
3. 建立核心公式清单，包括未编号但决定方法的表达式，以及理解正文所需的附录公式。逐项记录原式、编号、物理页、符号定义来源和待核实事项。不要用文字总结代替公式解释。
4. 对公式页调用 `zotero_render_pdf_page`，视觉核对上下标、求和范围、条件项、字体区别、正负号和式号。文本抽取中的公式顺序或字符可不可靠，不能直接“修复”为熟悉的标准公式。
5. 写讲解时读取 [references/explanation-patterns.md](references/explanation-patterns.md)，其中规定公式、重点和教学例子的具体质量标准。

## 可靠定位与批注

`read_pdf` 返回的 passage 可能只是排版的一行，并不等于一个句子。先在上下文中确定完整选段，再用 `zotero_find_pdf_text` 精确定位。

- 高亮或下划线默认从完整句子开头到结束标点，可包含连续多个完整句子。跨行仍保持同一条标注；不包含上一句残段或下一句开头。用户明确要求术语、短语、公式片段时按该边界选择。
- 检索使用 PDF 实际提取的英文原文，保留其断词、数学字符和空白规则；译文、解释、例子只写入 `comment`。不得拿概括句当被高亮原文。
- 使用工具返回的 opaque locator ID，不猜页内坐标。定位失败时回查该页和相邻文本；公式无法稳定定位时，可把解释写为锚定相邻完整介绍句的 `note`，并明确所解释公式的式号与页码。需要图像注释时，先看页面渲染，再用该 render ID 和实际图像像素矩形准备；不靠记忆推测矩形。
- 现有注释与拟新增注释在同一页、同一原文或公式区域且解释目的相同，则引用现有内容或跳过。去重跨注释类型：image/note 的 `text` 可能为空，需结合页码、锚定区域、式号与 comment 的解释目的判断，不能只匹配非空高亮文本。保留手工及已有内容。仅在当前工具实际支持原位更新时更新需要修复的注释；`status` 的更新标记不等于存在可调用的更新接口，不用新增重复注释冒充修复。
- 核心重点使用 `emphasis: important`，一般解释使用 `normal`。不指定 `color`，让插件偏好生效；用户指定颜色时遵从其选择。可使用便于检索的主题标签。
- `comment` 可保存 Markdown 源码，例如小标题、列表、`$...$` 或 `$$...$$`。Zotero 的批注窗是否渲染数学由客户端决定，不承诺其展示效果；独立 `.md` 文件保留完整 Markdown 和 LaTeX 源码。

## 论文自动标签

用户请求自动标注论文时，同时为论文父条目添加内容标签；仅请求自动标签或分类时，只执行阅读与标签流程，不额外创建批注和长篇讲解。仅请求讲解、摘要或预览时不写标签。用户已有授权时自主检查计划并应用，无需再次确认。

1. 发现 `zotero_get_item_tags`、`zotero_prepare_item_tags`、`zotero_apply_item_tags`。检查实际可调用能力，不能仅凭版本或 `item_tags` 标记宣称可写。
2. 使用返回的论文 `item_id` 读取已有标签；PDF ID 会解析到父条目。不要把主题标签只写在 PDF 或注释上。独立 PDF 没有父条目时报告限制，不自动新建文献。
3. 读摘要、方法及结论；分类证据不足时读相关正文。按内容选择通常 3–6 个稳定、便于检索的主题、方法和应用标签；不要根据题名猜测方法、堆叠宽泛关键词或添加无证据的评价。优先复用已有同义标签和用户用语，避免同一概念中英各写一份。若用户指定词表、语言或数量则优先遵从。默认保留通用英文技术术语。
4. 执行 get → prepare → 核对目标标题、已有标签、新增标签及各标签的原文依据 → apply → get 回读。接口只追加缺失标签并将新增标签标为 Zotero 自动标签（type 1）；保留原有标签和类型。计划过期或标签发生变化时重新读取和准备。
5. 只在回读确认后报告实际新增和已存在的论文标签。批注标签与论文标签分别核实。不能添加“已读完”等阅读状态，除非确实完成相关阅读或用户要求。

例如 Ctrl-World 在核对内容后可选择 `world model`、`robot manipulation`、`action-conditioned video generation` 等；示例不是固定词表，不给其他论文机械套用。

## 批注写入验证

对已获授权的新增批注，执行 `zotero_prepare_annotations` → 自主核对预览 → `zotero_apply_annotations` → `zotero_list_annotations`。

图像或公式裁剪使用 `zotero_prepare_image_annotation`，审阅实际裁剪预览后同样调用 `zotero_apply_annotations`。首次在该 PDF 或新的桥接版本创建文字高亮时，先应用一条有意义的完整句子，回读 `position.rects` 检查首尾边界与相邻行矩形是否重叠，再扩大批量；上下标造成的复杂几何需看原页。遇到真实定位或几何问题时保留已完成结果，不猜坐标覆盖原文。

核对每条预览的附件、页码、开头、结尾、相邻原文、locator 覆盖及 comment，确认没有选入下一句片段，且首尾行仅覆盖实际文字。发现问题时重新定位并准备正确批次；没有正确预览就不应用。若等待或阅读过程中规则版本发生变化，按当前规则重新准备。

仅将 `apply` 返回并由 `list` 回读确认的注释报告为成功。应用响应不确定时先 `list`，不要盲目生成新批次；同一 plan 的重试保持幂等，但不能把“已 prepare”说成“已写入”。部分失败时保留成功结果，报告失败部分和原因。

## Markdown 交付

组织方式按论文本身决定，通常包含论文与版本信息、阅读主线、重点解释、全部核心公式讲解、具体例子、实验结果与局限。每个解释给出物理页及章节/式号；PDF 印刷页码不同则另行标明。

保持三类证据清楚可辨：论文原文或结果、根据原文作出的解释/推断、为教学构造的例子。短引文辅助定位即可，不把整篇论文复制进交付文件。公式与数字按原始页面核对；符号维度或实验细节未说明时明确写“原文未说明”，不补成事实。

收尾给出 Markdown 文件链接，分别报告实际新增、正文引用的现有批注、跳过重复及失败数量，以及未解决的关键限制。“引用现有”是保留并在讲解中使用已有内容，不是一次新的写入；仅阅读过的批注不计作复用。只有在回读验证后才声明 Zotero 已完成注释。
