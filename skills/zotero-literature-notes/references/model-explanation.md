# 模型方法精读的写法

目标是让读者能沿数据流理解一次训练和一次部署，而非只记住模块名。默认中文连贯解释，公式、图、原文和文献在解释所需的位置出现。用户提供风格样例时先实际读取；访问失败应说明并请求片段，不能声称已模仿未读到的内容。

## 开头与文献范围

文件位置先按 `SKILL.md` 读取实际 Zotero 分类层级确定；命名或独立重生成不能改变已确认的分类父路径。完整论文题目用作真实笔记文件名，由 Obsidian 内联标题显示；文件名中的 Windows 禁用字符做最小替换。启用内联标题时正文不再添加重复 H1，直接用“发表日期、期刊/会议”简洁表格呈现元数据，按 `SKILL.md` 的发表信息规则区分预印本日期与正式发表日期。正文第一段直接说明研究问题、现有方法的矛盾和本篇核心思路，不再复述题名或写作者/版本/页数介绍段。

文献比较默认来自本篇原文实际引用、讨论或用于实验对照的工作。先确认其原文出处，再穿插到相关解释中；历史对话出现过、Obsidian 有同主题笔记或可以设想方法结合，都不足以加入正文对比。当前用户明确要求额外比较时再展开，并说明这是拓展分析。

## 建立计算过程

先给出任务、输入输出和最小完整流程，再沿实际计算顺序讲每个模块。每个关键机制回答：为什么需要它、输入来自哪里、如何计算、输出交给谁、哪些变量更新/冻结、相对先行工作改变了什么。保持语言流畅，不机械地把每个模块写成六个相同标题。

区分真实观测、训练目标、推理噪声、中间隐藏状态和最终生成结果。逐一明确时间轴、token 轴、网络深度轴和 batch/head/channel 轴；不要把帧数等同 token 数，把稀疏通信等同删层，或把中间未来表征等同生成好的未来视频。

## 公式逐项讲清，并用数字走通

每个展示出来的公式都要让读者知道“每个量是什么、为什么这样算、算完得到什么”。保留现有沿数据流展开的结构，在相关模块附近解释公式，不另堆一个与方法脱节的公式列表。先说公式解决的具体问题，再给出原式及核实过的原文编号/页链接；自己拆解、等价改写或教学推导时明确标注，不能赋予它原论文的公式编号。

### 每个变量都要有解释

首次出现的公式逐一说明全部变量、参数、常量、函数、集合与索引，包括等号左侧的结果。符号较多时在公式下用紧凑表格列出“符号｜含义与来源｜形状/范围｜作用”，再用自然段讲计算。不要只解释 Q/K/V 而漏掉缩放维度、投影矩阵、掩码、索引集合或输出。每个关键公式下就近给出完整符号说明，包括复用的变量；旧变量可简短重述，但不能让读者仅靠翻找前文猜含义。函数参数、参数集、帽子/波浪号及每个上下标都要覆盖。原文公式与解释性依赖式同样适用，不能用“这是示意”省略变量解释；每个公式都不能留未定义的新符号。同一符号在不同章节换了含义时重新解释。

- **含义与来源**：它表示真实观测、监督目标、噪声、隐藏状态、模型输出还是可学习参数；来自哪个模块、由什么输入计算。需要时说明训练/推理中是否更新、冻结、采样或缓存。原文未说明的状态不能补猜。
- **上下标与索引**：解释每个上标/下标、帽子、横线、粗体及集合的含义；区分模态标记、stage/层索引、帧/token 索引、批次、噪声时间与真实执行时间。明确求和/取样的索引范围，区分上标作为标签、转置或幂的情况。
- **形状与范围**：张量按实际采用的轴给出可核实的形状，向量、矩阵、标量与集合分别说明；概率权重、时间、步长说明取值范围。数学关系能确定的符号维度可以给出，论文未披露的具体维度标明未披露，教学选值单独注明。

### 运算和数据流都要展开

解释矩阵乘法、逐元素乘法、拼接、加权和、转置、广播、softmax、范数、期望和导数实际作用于哪些轴。把复杂式子拆成有明确中间结果的几步，逐步说明输入/输出形状为何兼容，以及哪一维变大、缩小或保持不变。例如注意力要说明查询/键/值分别来自谁、缩放项为何出现、掩码限制什么位置、softmax 沿哪个键轴归一化、输出为何仍对应查询位置。

运算讲完，把结果接回模型：谁使用这个输出，它改变了哪一步，为什么这种计算支持论文所说的缓存、融合或条件控制。损失公式要说明预测与目标怎样对应、对哪些维度/样本求平均、梯度能到达哪些参数；噪声路径和积分式要说明端点、方向、步长符号与条件。仅说“某符号表示某参数”或翻译公式名称不能代替机制解释。

### 保留并加强具体数字例子

每个核心机制配一个小而完整的数值演示；相邻公式优先共用一个贯穿例子，简单代入式可以接着前一步算，不机械地重复新建例子。先明确输入数字、教学维度和必要假设，再列中间计算、最终输出及其含义，不能只给未经计算的假设场景或最终答案。所有展示公式的符号仍需解释，不能用例子替代符号定义。

例如加权融合可用两个位置对齐的向量 $v_1=[2,4]$、$v_2=[6,8]$ 和权重 $\alpha_1=0.25$、$\alpha_2=0.75$，算出 $\bar v=0.25[2,4]+0.75[6,8]=[5,7]$；同时说明 $v_1,v_2$ 是教学输入向量，$\alpha$ 是融合权重，$\bar v$ 是融合输出，权重和为 1，向量长度保持 2。若论文机制同时融合 K 和 V，例子也要展示二者使用同一组权重，不只计算一个无关的向量平均。

注意力例子应算出至少一行打分、归一化权重及输出；采样/速度场例子应把一个时间点或一步更新实际算出来；损失例子应展示预测、目标、差值和归约。按机制选合适的小规模例子，不强行让所有机制共用同一种演示。数字近似时写清舍入，必要时用计算工具核对。检查概率和、归一化轴、形状、符号方向和边界值，确保例子遵循论文公式。

所有自选数字明确标为**教学示例，非论文实测或真实配置**；不得把教学步数、维度、随机噪声或示意求解器写成作者实现。例子应帮助理解该论文实际机制；未披露的交互索引、维度或代码细节仍须说明未知。

## 训练与推理各走一遍

分别讲清监督数据如何构造、噪声/时间怎样采样、损失回传到哪些模块，以及部署时哪些分支只算一次、哪些反复计算、何时更新缓存。生成模型要明确 clean/noise 端点、积分方向和速度场的意义。伪代码是解释示意时应标明，不把 Euler 演示当成作者实际求解器。

## 文献、图表与证据就近出现

每篇相关论文先检索 Zotero，按 `SKILL.md` 的“来源引用优先 Zotero”核对并选择跳转：本库条目用 Zotero，具体原文证据用已核实的 PDF 页链接，未收录才用网页。原文在本库时，不用 arXiv 网页承载页码/图表引用。

把已确认在原文引用/讨论范围内的相关论文引用放在讨论具体方法的句子旁，例如讲 flow matching 时引用其原论文，讲 MoT 时对照其专家组织方式，讲缓存时比较现有方法的更新依赖。用一句话解释继承、差异或证据边界，不仅列题名和链接。只写已从原文/作者材料核对的关联，不因命名相似就宣称继承。

把 Zotero 原文提示框、结构图、表格插在对应解释附近，保留完整来源内容和启用的链接。原文长选段可以折叠为 `[!quote]-`；图表保持易见。不要把所有原文与文献堆在笔记末尾。参考表可作辅助索引，但不能代替就近引用。

实验说明每个对照控制什么、改变什么、支持多强的结论。累计消融、重训练对照与同 checkpoint 推理改动分别解读；速度须核对测量边界和硬件。将作者报告、解释性推导和未验证猜想分开。

## 交付是可读的笔记

正文不显示 HTML 管理注释、内部 annotation ID 列表或执行流程说明。Bridge 管理标记用 `scripts/note_metadata.py` 存入旁侧元数据，后续同步前恢复，最终清理。只清理已识别的管理注释，保留图片、公式、代码、普通用户内容和有效来源链接。

读完后应能回答：一次调用中每个模块做什么，模型为何能缓存/融合/稀疏交互，训练与部署的差异是什么，实验在哪些条件下支持设计。若只能复述模块名称，方法解释仍需展开。

修改现有笔记时，必须把这套要求落实到该笔记的公式段，再检查成稿；只改 skill 不等于已经补齐现有笔记。不同用途的同名符号应重命名或明确区分，例如交互 stage 数 $M$ 与注意力掩码 $\mathcal M$。
